## 二、下一步要做的功能（按优先级）

### P0 · 必做（决定项目成色）

**1. 单文件拆分为多文件（所有并行开发的前提）**
现状：所有 HTML/CSS/JS 挤在 `index.html` 里（584 行）。三个人同时改同一个文件，每次 push 都会冲突，无法并行。

拆分方案：

```
index.html          结构骨架（谁改都要先说一声）
assets/styles.css   全部样式
assets/app.js       入口：初始化、模式路由、事件绑定
assets/api.js       云端数据层（fetchAll / publish / delete）
assets/search.js    检索算法（文本 + 图像）
assets/ai.js        大模型调用（出题、判答、图片打标签）
assets/ui.js        Toast、弹窗、上传组件、渲染
```

拆分后每人拥有不同文件，冲突概率降到接近 0。

**2. 接入真实 AI（WorkBuddy 云服务免密钥通道）**

- 视觉打标签：发布时用 `glm-4.6v` 看图生成结构化描述（类别/颜色/品牌/显著特征），存入 `ai_desc` 字段；
- 语义检索：检索词与 `title + ai_desc + detail` 做语义匹配（先由模型做关键词扩展与相关性打分，不必上向量库）；
- AI 出题判答：读隐藏细节 → 动态生成 1 个只有失主能答的问题 → 判定回答是否吻合，支持用户上传照片对答案；
- 硬性规范（不遵守会直接报错）：
  - 必须 `stream: true`，非流式会被 SDK 拒绝（`request_stream_required`）；
  - `messages[0]` 必须是 `system` 消息，否则请求失败；
  - 加节流：同一浏览器 60 秒内最多 3 次 AI 调用，防止额度被刷；
  - 发布/删除/回答都做输入清洗，防提示注入（不要让用户输入拼进 system）。

**3. 图片上传体验**
- 支持**粘贴上传**（`paste` 事件读剪贴板图片）；
- 支持**拖拽上传**（`dragover` / `drop`，带高亮反馈）；
- 保留点击选择与压缩逻辑。

### P1 · 强烈建议

**4. 对话式录入 / 取物（打开即选模式）**
- 首屏加两个大按钮：「📤 我丢了东西」「🔍 我来找东西」，进入不同对话流；
- 录入流程改成多轮追问：名称 → 照片 → 最后见到的地方 → 只有失主知道的细节；
- 取物流程：一句话描述 → 候选卡片 → 点认领 → AI 提问确认。
- 实现建议：先做“分步表单 + 对话气泡样式”，比真做成自由对话更稳、更好演示。

**5. 位置智能填写**
- 调浏览器 `navigator.geolocation` 拿当前坐标 → 用腾讯位置服务逆地址解析出“XX 路 XX 号附近”文字 → 填入输入框，用户可改；
- **合规红线**（必须遵守）：
  - 地图服务只能用腾讯地图/高德/百度/天地图，**禁止** Google Maps、OpenStreetMap、Mapbox 等；
  - 走 WorkBuddy 默认代理模式时前端不出现 Key（`_TMapSecurityConfig` 须在 SDK 之前设置，SDK URL 不带 `key`）；
  - 坐标系用 GCJ-02；
  - **不要把精确坐标存进公开数据库**——只存用户确认后的**文字地点**（约 50 米精度描述即可），否则违反个人信息保护法对他人位置数据的要求；
  - 用户拒绝授权时降级为纯手填，不阻塞流程。

**6. 认领归属与防误删**
- 简单身份：昵称 + 浏览器生成的固定 ID（`localStorage`），发布时写入 `owner_id`；
- 只允许删除自己的记录（云库 RLS 收紧，或前端 + 服务端双校验）。

### P2 · 锦上添花

- 图片改走对象存储（不再 base64 塞数据库）
- 列表分页 / 无限滚动
- 移动端适配打磨（间距、点击区、字体）
- 认领成功后的双方联系方式交换（脱敏）
- 自动部署（推 main 即发布），需先稳定再开

## 五、账号 / 积分 / AI 调用怎么分

- **云服务应用与积分**：全部挂在组长（A）的 WorkBuddy 账号下，所有 AI 调用消耗 A 的积分；量级很小（一次出题判答约 0.11 倍率 × 千余 tokens），开发期可忽略。
- **模型选择约定**：
  - 视觉打标签：`glm-5.3-flash`（实测 4.6v 被网关拒绝）
  - 出题/判答（纯文本）：`glm-5.3-flash`（低倍率）
  - 批量调试压测：`hy4free`（0 积分），正式演示切回上面两个
- **队友调试建议**：想大幅试错 AI 逻辑时，各自在自己 WorkBuddy 里开一个云应用当"沙盒"，不消耗主账号积分；线上共享数据仍走主应用。
- **真要分摊成本**：把整个项目迁到某位队友账号重建（换一次公网链接、重录数据），或将来改用自申请 API Key + 后端（按量付现金，更可控）。
- **GitHub 账号**：每人自己的账号 + 自己的 Token，绝不能共用组长的。

## 六、常见坑（踩过就记下来）

1. **不要双击本地 index.html 测试** —— 域名校验会拦住云端与 AI，必须走线上链接；
2. **改动要重新发布才上线** —— push 只进仓库，不影响线上；
3. **AI 调用必须 `stream: true` + `system` 消息**，否则 SDK 直接报错；
4. **地图只能用白名单厂商**，且不要把精确定位坐标写进公开数据库；
5. 图片仍然 base64 入库，物品多了会拖慢加载 —— P2 再改对象存储。

## 七、三条工作线（正式分工，2026-11）

> 原则：**每人拥有独立文件**；跨线调用只通过下方"接口契约"，不改别人的文件。

### 接口契约（A 先交付，B/C 照此调用，先放空实现也行）

```js
// assets/api.js —— 数据层
listItems()                        // → [{id,title,detail,location,image,aiDesc,status,ownerId,...}]
createItem(item)                   // → {ok, id}
deleteItem(id)                     // → {ok}
updateItem(id, patch)              // 认领、归档等状态变更
// assets/ai.js —— AI 能力（内部自动处理 stream/system/节流）
describeImage(dataURL)             // → {desc, tags[]}  视觉打标签
expandQuery(text)                  // → {keywords[]}    检索词扩展
makeQuestion(detail)               // → {question}      出题
judgeAnswer(detail, question, ans, ansImageDataURL) // → {pass:boolean, reason}
```

### A · 组长 —— AI Agent 接入线（拥有 `assets/config.js`、`assets/api.js`、`assets/ai.js`、云库结构）

| 任务 | 验收标准 |
| --- | --- |
| 云库加字段 | 新增 `ai_desc`、`ai_tags`、`status`、`owner_id`、`claim_at`，RLS 仍可公开读写 |
| 视觉打标签 | 发布时自动生成 30–80 字描述 + 3–6 个标签，落库 `ai_desc`/`ai_tags` |
| 动态出题 | 每次进入确认流程，问题文案由模型生成，同一条记录多次进入**问题不重样** |
| 判答 | 答案明显错/含糊判不通过；能带图作答，模型看图判断是否同一物品 |
| 节流与安全 | 同一浏览器 60 秒 ≤3 次 AI 调用；用户输入不入 system；失败有降级文案 |
| 模型约定 | 视觉/文本 `glm-5.3-flash`，压测 `hy4free`（0 积分） |

### B · 前端交互线（拥有 `assets/ui.js`、`assets/styles.css`、`assets/app.js`）

| 任务 | 验收标准 |
| --- | --- |
| 粘贴上传 | 在录入页 `Ctrl/Cmd+V` 直接贴入截图，自动压缩并预览 |
| 拖拽上传 | 拖到上传区高亮，松手即上传；非图片文件给明确提示 |
| 双入口首页 | 打开页面先选「我丢了东西 / 我来找东西」，之后才见到对应表单 |
| 对话式流程 | 分步气泡式追问（名称→照片→地点→隐藏细节），可回退上一步、可跳过 |
| 位置填写 | 一键读当前位置 → 反解为"XX 路附近"文字，可手改；拒绝授权则纯手填 |
| 移动端 | 375px 宽度下无横向滚动、按钮可点区域 ≥44px |

### C · 匹配质量与生命周期线（拥有 `assets/search.js`、`assets/match.js`、`assets/stats.js`、`tests/`）

| 任务 | 验收标准 |
| --- | --- |
| 检索升级 | 用 `expandQuery` 做同义词/近义扩展，支持错别字与拼音首字母；"丢了耳机"能召回"蓝牙耳机" |
| 图片检索升级 | 改为比对 `ai_desc`/`ai_tags` 的语义相似度（颜色特征作为兜底加分项），不再只看颜色 |
| 相关性排序与置信度 | 结果卡片显示匹配度（高/中/低），高分前置，低于阈值给"没找到？试试这些" |
| 认领流程 | 认领记录表 + 状态流转（待确认→已确认→已归还），我的认领列表可见 |
| 到期归档 | 超过 30 天未认领自动标记过期，默认不在检索结果里出现，可手动恢复 |
| 统计看板 | 按类别/地点/时间统计失物分布（简单条形图），用于演示"数据洞察" |
| 质量保障 | 三浏览器 × 四主流程测试矩阵，Bug 清单（截图 + 复现步骤），20 条演示种子数据 |

3. PR 描述写清"改了什么 + 怎么验收"，截图附上；
4. A 收到"改完了"后统一发布，链接不变。
