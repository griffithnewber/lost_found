# 强制登录改造（2026-11-05）

## 为什么做

测试时发现：**未登录也能发布**。发布记录的 `owner_id` 落的是"本机设备 ID"（`lf_owner_id`，随机串），
而留言收件是按 `物品.owner_id === 我的账号 ID` 过滤的。于是：

1. 游客发布一条失物 → `owner_id = u_bq7nhvh...`（设备 ID）
2. 别人来留言 → 留言正常入库
3. 发布者登录 → 自己的 ID 变成 `u_用户名`
4. 信箱里永远看不到这条留言，**这条记录也没人再能操作**（既不在"我的发布"，也没法确认认领）

## 现在的规则

| 动作 | 未登录 | 说明 |
|---|---|---|
| 打开网站、逛广场、看检索结果 | ✅ 可以 | 游客只读，「随便看看」入口保留 |
| 发布（分步向导 / 传统表单） | ❌ 拦截 | 弹登录框，说清"别人联系你时才收得到" |
| 给发布者留言 / 联系 | ❌ 拦截 | 登录成功后自动把留言框接着打开 |
| 看留言线程、回复、确认认领 | ❌ 拦截 | 同上，登录后自动继续 |
| 信箱、我的发布 | ❌ 提示登录 | 信箱原来就有登录墙 |

## 代码改动

| 文件 | 改动 |
|---|---|
| `assets/auth.js` | 新增 `LF.auth.require(why, onDone)` 统一闸门；登录/注册成功后 `afterAuth()` → 广播事件 → 收养历史匿名发布 → 执行待续动作；关掉登录框会清空待续动作 |
| `assets/api.js` | 新增 `LF.api.adoptLocalItems()`：把 `owner_id` / `sender_id` 还停在本机设备 ID 上的物品与留言，全部迁到当前账号，然后删除 `lf_owner_id` |
| `assets/app.js` | 两个发布函数开头加闸门；首屏「我丢了东西 / 我捡到了东西」改为先登录再进发布（登录后自动继续）；「随便看看」游客进广场；点发布 tab 时给未登录提示 |
| `assets/contact.js` | `openFinder` / `openThread` 加闸门，登录后自动续做；发送按钮再兜底校验一次 |

## 历史数据怎么救

- **同一台电脑、同一个浏览器**发的匿名记录：登录后打开页面会自动收养，提示「已把本机匿名发布的 N 条记录归到你的账号下」。
- **无痕窗口 / 另一台设备 / 换了浏览器**发的：本机没有那个设备 ID，自动收养无能为力，只能后台按记录 ID 手动改 `owner_id`。

已实测云端权限（临时记录验证后已删除）：按 `owner_id` 条件查询、批量 `PATCH` 更新、删除都可用。

## 给 B / C 的注意事项

1. 新增任何"写"入口（发消息、改状态、删记录），第一行都加：
   ```js
   if (!LF.auth.userId()) { LF.auth.require('提示语', function () { 重新调用自己 }); return; }
   ```
   不要用 `if (!LF.auth.require(...)) return;` 再在回调里调用自身 —— 已登录时 `require` 会立即执行回调，会无限递归。
2. 渲染层不要再出现"当前设备 ID"这个概念，一律用 `LF.api.ownerId()`（登录后用账号 ID）。
3. 未登录时不要渲染"我的发布"里的删除/确认按钮作为可用状态。
