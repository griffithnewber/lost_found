## 2. 三个可行性结论（先说清，别开工时才发现）

1. **对话端定位：放弃。** 阿寻的对话里没有位置消息这种输入类型，提示词也没有任何定位工具可调。替代：登记流程把「地点」拆成两问——先从七个区域里确认一个（可从口述推断，让用户确认），再追问楼栋/楼层细节（进 `location` 私有列和 `notice`）。
2. **网页端定位：能做，但只做"就近推荐"。** `navigator.geolocation` 在 HTTPS 页面可用；拿到坐标后**只在内存里**跟七个区域中心算一下距离、推荐最近区域填进表单/提示给用户，**坐标立刻丢弃、绝不入库**。这是 `ROADMAP.md` 合规红线（精确坐标不入公开数据库）下的唯一合规用法。拒绝授权就纯手选，不阻塞。
3. **底图：先用零依赖 SVG 示意图，别急着接地图厂商。** 高德/腾讯 JS API 都要 key（还得放后端代理），评委演示没必要冒这个险。SVG 底图是项目自有资产：路线、湖、建筑块都是画出来的示意，将来想换真实感，直接把 `<image href="campus.jpg">` 垫底、标记层原样保留。**合规提醒**：将来若接真实地图，厂商只能用腾讯/高德/百度/天地图（白名单），坐标系 GCJ-02，key 走代理（`ROADMAP.md` 原话）。

## 3. 数据层（A 线 · 一个迁移文件）

### 3.1 为什么必须加新列

`2026-11-07_harden_public_columns.sql` 之后，网页只能读白名单列（id/title/image/notice/category/…/pickup_location），`location` 具体地点是**私有的**——这是防冒领设计，不能为地图开倒车。地图只需要"哪个区域"这种粗粒度信息，所以：

> **新增 `area` 列（text，七区枚举，可 NULL），并加进网页 SELECT 白名单。**
> 精度 = 区域级（约一栋楼群），不违反合规红线；具体到楼层座位的信息仍锁在 `location` 里。

### 3.2 七区配置（唯一事实源，前后端和阿寻共用）

| 代码 | 名称 | 底图坐标 (x,y)① | 角色 |
|---|---|---|---|
| `east_teaching` | 东教学楼群 | (640, 280) | 区域 + 寄存点 |
| `west_teaching` | 西教学楼群 | (360, 280) | 区域 + 寄存点 |
| `east_playground` | 东操场 | (810, 430) | 区域 + 寄存点 |
| `west_playground` | 西操场 | (190, 430) | 区域 + 寄存点 |
| `east_dorm` | 东园宿舍 | (660, 570) | 区域 + 寄存点 |
| `west_dorm` | 西园宿舍 | (340, 570) | 区域 + 寄存点 |
| `gym` | 体育馆 | (500, 130) | 区域 + 寄存点 |

① **坐标是示意占位**（画布 1000×700），按真实校区平面图校准——只改配置文件里的数字，代码零改动。校准方法：把真实校区图垫在 SVG 底下，逐区点出中心坐标填回来。

统一放 `assets/zones.js`（`LF.zones` 数组：`{code, label, x, y}`），网页渲染、阿寻提示词、回填 SQL 三处引用同一份。

### 3.3 迁移 SQL（`db/migrations/2026-11-09_map_area.sql`，要点）

```sql
-- 物品表：粗粒度区域（公开）；具体位置仍在私有列 location
ALTER TABLE public.lost_items ADD COLUMN IF NOT EXISTS area text;

-- 寄存点表：挂到区域（渲染用；没有的行地图上不画）
ALTER TABLE public.locations ADD COLUMN IF NOT EXISTS zone text;

-- ⚠️ 关键：把 area 授给网页，否则前端一查就 401（harden 迁移的教训）
GRANT SELECT (area) ON TABLE public.lost_items TO anon, authenticated;
GRANT SELECT (zone)  ON TABLE public.locations TO anon, authenticated;
```

回填（历史记录没有 area，按 notice 里的关键词猜，猜不出留 NULL，**宁缺勿错**）：

```sql
UPDATE lost_items SET area='east_teaching'
WHERE area IS NULL AND (notice ilike '%东教%' OR notice ilike '%东教学楼%');
-- 其余六区同理；pickup_location 有值的按寄存点名称反查
```

### 3.4 上线顺序（照 harden 迁移的坑再来一遍就难看了）

**先跑迁移（加列 + 授权）→ 再发前端 → 最后更新阿寻提示词。** 顺序反了会出现：旧前端 select 不带 area（没事），但新阿寻写入带 area 而列不存在（报 42703）。

## 4. 阿寻提示词改动（A 线 · 版本 1.17.0）

| 位置 | 改动 |
|---|---|
| 分支 A 第 3 项「捡到地点」 | 拆两问：① 从七区里确认一个（用户口述里能推断就直接说"我理解是东教学楼群，对吗？"，推断不了就列七个让他挑）；② 追问楼栋/楼层/座位区（写进 `location` 私有列 + `notice`，规则照旧） |
| 分支 B5 寻物登记 | 同样拆两问（丢失地点） |
| 「数据与工具」两条 INSERT | 参数表各加一个 `area`（第 N 个参数，英文枚举值）；字段对照加 `area` 一行：**七区枚举之一，网页地图靠它定位，只存区域不存坐标** |

| 分支 G/H、补照片、登录墙 | 不动 |

提示词里写死七区枚举清单（代码+中文名），并注明"用户说的位置对不上任何一个区时，让他挑最接近的，不要自造第五个区"。

## 5. 前端模块设计（B 线 · 新文件 map.js / map.css / zones.js）

### 5.1 挂载位置：广场面板内部，不做独立 tab

```
panel-square
├─ card 筛选栏（新增，§7 的 chips + 现有 square-search 同排）
├─ card 地图（新增，LF.map 挂载点 <div id="campus-map">）
│   ├─ 图层1 寄存点（可开关）
│   └─ 图层2 物品 emoji
└─ #square-list（现有卡片列表）
```

理由：你要的"一边地图一边广场、点标记锁卡片"就是联动视图，拆成两个 tab 反而断开；现有 square.js 已有 20 秒轮询和卡片缓存，地图直接吃同一份数据，零额外请求。

### 5.2 物品标记

- **emoji 映射**（category → emoji，写在 zones.js 旁的 config 里）：
  `headphones 🎧 / card 🪪 / cup 🥤 / keys 🔑 / wallet 👛 / phone 📱 / bag 🎒 / umbrella ☂️ / glasses 👓 / book 📚 / clothes 👕 / other 📦`
- **found vs lost 区分**：found 实心 emoji；lost（丢了在找的需求）半透明 + 虚线描边圈——缩小看全貌时一眼分清"已捡到待认领"和"还在找"。
- `area IS NULL` 的旧记录：归入画布角落的「未定位」收纳点（灰色 ❓），点开提示"这条没登记区域，让阿寻补一下 area"——**不默默丢数据**。

### 5.3 寄存点图层（防重叠的核心设计）

- 数据源：`locations` 表（`zone` 列非空的行），渲染 = 区中心锚点上画 📍 + 名称缩写；寄存点**永远画在正中心**，物品标记**从锚点向外环形散开**（同区第 n 个物品偏移 n×14px，按 id 排序）——两层天然不重叠。
- 图层开关：地图右上角一个小按钮「📍 寄存点 显示/隐藏」，默认显示。
- 寄存点的"按编号录入"走现有流程不变（阿寻分支 A 第 7 项选寄存点），地图只是把 `locations` 画出来，不新增录入入口。

### 5.4 缩放与平移（严格按你的操作习惯）

| 端 | 手势 |
|---|---|
| 电脑 | **Ctrl + 滚轮**缩放（不拦普通滚轮，页面照常滚）；双击 +25%；按住拖拽平移 |
| 手机 | 双指捏合缩放、单指拖拽平移（`touch-action: none` 只设在地图容器上） |
| 通用 | 缩放范围 1×–5×，以光标/双指中点为缩放中心；初始 fit 全图；「⤢ 复位」小按钮 |

实现不引库，纯 CSS `transform: translate(x,y) scale(s)` + 指针事件，约 150 行；P2 想要更顺滑再考虑引入库。

### 5.5 双向联动（地图 ⇄ 广场）

- **点地图标记** → `square.js` 按 `data-id` 找到卡片 → 滚动到可见 → 复用现有深链高亮样式（`#item-<id>` 那套）闪两下。
- **点广场卡片上的「🗺️」小图标**（或悬停）→ 地图上该标记放大脉冲一下；卡片已在视口时地图同时平移把标记带到中心。
- 过滤联动：chips 过滤后，地图只画过滤后的集合（图层同步，别各滤各的）。

## 6. 广场筛选标签（§7 的 chips，单独说清行为）

顶部一排（复用现有 tab 样式，做成 ghost chip）：

```
[ 全部 ] [ 📦 捡到的 ] [ 🔍 丢了在找 ] [ 📍 寄存点 ]
```

- **捡到的** = `post_type='found'` 且 status open/claimed；**丢了在找** = `post_type='lost'` 同理；**寄存点** = 不是物品过滤，而是切换成寄存点列表视图（名称+位置+开放时间，数据来自 locations）+ 地图上只亮寄存点图层。
- 与 `square-search` 输入框是 **AND** 关系；chips 是单选（不做成多选矩阵，标签一多就乱——按你说的"统一成一个标签"原则）。
- 默认「全部」，刷新/轮询后保持当前选择。
